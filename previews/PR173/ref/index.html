API reference

Names that are not exported are listed with the DataAugmentation. prefix and need to be imported or qualified. The sections Extending and Testing cover the names used for defining your own items and transformations.

Jump to the symbol index.

Items

DataAugmentation.Image — Type
Image(image[, bounds]; interpolate=BSpline(Linear()), extrapolate=zero(T), antialias=false)

Item representing an N-dimensional image with element type T. Optionally, the interpolation and extrapolation method can be provided. Interpolation here refers to how the values of projected pixels that fall into the transformed content bounds are calculated. Extrapolation refers to how to assign values that fall outside the projected content bounds. The default is linear interpolation and to fill new regions with zero.

Set antialias = true to apply a box prefilter when an affine projection downsamples the image. The interpolation, extrapolation and antialiasing settings stay with the image through projective transforms.

Info

The Interpolations package provides numerous methods for use with the interpolate and extrapolate keyword arguments. For instance, BSpline(Linear()) and BSpline(Constant()) provide linear and nearest neighbor interpolation, respectively. In addition Flat(), Reflect() and Periodic() boundary conditions are available for extrapolation.

Examples

using DataAugmentation, Images

imagedata = rand(RGB, 100, 100)
item = Image(imagedata)
showitems(item)

If T is not a color, the image will be interpreted as grayscale:

imagedata = rand(Float32, 100, 100)
item = Image(imagedata)
showitems(item)

DataAugmentation.ImageBatch — Type
ImageBatch(images, labels)
ImageBatch(images, class_indices; num_classes)

An item for collated images and their classification labels. Use one-based real arrays of size (width, height, batch) for grayscale images or (width, height, channels, batch) for tensors collated after ImageToTensor. Volumes collated after ImageToTensor have size (width, height, depth, channels, batch): from four dimensions on, the last one is the batch, the one before it the channels, and all the dimensions before those are spatial. The label matrix has size (classes, batch) and holds one-hot or soft labels. The second constructor encodes class indices in 1:num_classes as Float32 one-hot columns. itemdata returns (images, labels).

DataAugmentation.BoundingBoxes — Type
BoundingBoxes(data, bounds; format = :XYXY, labels = nothing)

A collection of axis-aligned boxes on a two-dimensional canvas. Pass a one-based 4 × N matrix of real coordinates with one box per column. Give the canvas as (height, width) or as Bounds with row and column ranges. Optional labels is a one-based vector with one entry per box.

The coordinate order is (x, y), with x along columns and y along rows. Pixel i is centered at coordinate i, so a canvas axis a:b spans the continuous interval [a - 0.5, b + 0.5]. Supported formats are:

  • :XYXY for (xmin, ymin, xmax, ymax)
  • :XYWH for (xmin, ymin, width, height)
  • :CXCYWH for (xcenter, ycenter, width, height)

Use itemdata for the coordinate matrix, boxes.format for its format, and boxes.labels for the labels. Geometric transforms enclose the four projected corners of each valid box and update the canvas. Use ClampBoundingBoxes and SanitizeBoundingBoxes to clip or remove boxes after a crop or warp.

DataAugmentation.Rotate — Type
Rotate(γ; expand = true, center = nothing, fill = nothing)
Rotate(distribution; expand = true, center = nothing, fill = nothing)
Rotate(α, β, γ)
Rotate(α_distribution, β_distribution, γ_distribution)

Rotate spatial data around its center, by angles given in degrees. Rotate(γ) takes the dimensionality from the item. In 2D, it rotates by an angle chosen uniformly from [-γ, γ]. In 3D, it is the same as Rotate(γ, γ, γ): a rotation around each of the three axes, by angles chosen independently from [-γ, γ]. Use Rotate{2}(γ) or Rotate{3}(γ) to accept only 2D or 3D data.

Rotate(α, β, γ) is a 3D rotation by angles chosen uniformly from [-α, α], [-β, β], and [-γ, γ], for X, Y, and Z rotations.

You can also pass any Distributions.Sampleable from which the angle is selected.

expand = false keeps the input bounds. Pass an absolute center = (row, column) (or one coordinate per dimension in 3D) in pixel coordinates to rotate around another point. By default, out-of-bounds samples use the item's extrapolation setting. An explicit fill value applies to this rotation only and to Image items only; masks keep their own extrapolation. Rotations with a fill are not projective transforms and are not fused with neighboring ones.

Examples

tfm = Rotate(10)
tfm(Image(rand(Float32, 16, 16)))
tfm(Image(rand(Float32, 16, 16, 16)))

tfm3d = Rotate(10, 20, 30)
tfm3d(Image(rand(Float32, 16, 16, 16)))

DataAugmentation.WarpAffine — Type
WarpAffine(σ = 0.1) <: ProjectiveTransform

An affine warp calculated by randomly moving N + 1 corners of an N-dimensional item, which is three corners of an image. Similar to a random translation, shear and rotation. The corners move by up to σ times the geometric mean of the side lengths.

source
DataAugmentation.RandomAffine — Type
RandomAffine(degrees; translate = (0, 0), scale = (1, 1), shear = 0)

Apply a random 2D affine warp on the original canvas. A scalar degrees samples a rotation symmetrically around zero; a pair gives the angle limits directly. translate gives maximum fractions of the height and width. Sample a uniform scale from the two limits in scale. A scalar shear samples horizontal shear symmetrically, a pair sets its limits, and four values give horizontal then vertical shear limits. Angles are in degrees.

DataAugmentation.RandomPerspective — Type
RandomPerspective(distortion_scale = 0.5; p = 0.5)

With probability p, warp a 2D canvas by moving its four corners inward. distortion_scale runs from zero to one and controls how far each corner can move along each axis. The output keeps the original canvas bounds.

source
DataAugmentation.ElasticTransform — Type
ElasticTransform(alpha, sigma = 5)
ElasticTransform(; alpha = 25, sigma = 5)

Apply a smooth random elastic deformation to 2D spatial data. alpha scales uniform noise in [-1, 1] that is smoothed with a Gaussian of scale sigma (in pixels); either may be a scalar or a (row, column) pair. The same deformation is used for images, masks, and keypoints.

The sampled field is reduced when necessary to keep its displacement map contractive, which makes the backward map used for image sampling well-defined and numerically invertible. This caps the deformation: for small sigma, increasing alpha beyond some point has no effect. Increase sigma to allow larger, smoother displacements.

source
DataAugmentation.Project — Type
Project(P)

Projective transformation that applies the fixed projection P, a CoordinateTransformations.Transformation, regardless of the item's bounds.

source
DataAugmentation.PinOrigin — Type
PinOrigin()

Projective transformation that translates the data so that the upper left bounding corner is at the origin (0, 0) (or the multidimensional equivalent).

Projective transformations on images return OffsetArrays, but not on keypoints. Hardware like GPUs do not support OffsetArrays, so they will be unwrapped and no longer match up with the keypoints.

Pinning the data to the origin makes sure that the resulting OffsetArray has the same indices as a regular array, starting at one.

Crops and padding

DataAugmentation.Crop — Type
Crop(sz[, from]; padding = 0, pad_if_needed = false, fill = nothing, padding_mode = :constant)

Crop a region of size sz from the bounds of an item. from is FromOrigin() (default), FromCenter() or FromRandom(); see also CenterCrop and RandomCrop.

sz is a tuple with one size per dimension. An integer sz is the same size along every dimension, so that Crop(32, FromRandom()) crops a square from an image and a cube from a volume. An integer padding is the same for all dimensions, too; any other form of padding fixes the dimensionality.

With symmetric padding (one integer for all axes or one per axis), the bounds are extended on both sides before cropping. See Pad for asymmetric padding and the available padding modes. By default, padded pixels use the item's extrapolation setting, including when sz exceeds the bounds. With pad_if_needed = true, each side of an undersized axis is padded by the shortfall before choosing the crop. fill applies to Image items only; masks use their own extrapolation. With pad_if_needed, fill or a non-constant padding_mode, the result is a plain transform that is not fused with neighboring projective transforms.

Examples

tfm = Crop((32, 32), FromRandom(); padding = 4) |> PinOrigin()
tfm(Image(rand(RGB, 32, 32)))
source

CenterCrop(sz; padding = 0, kwargs...)

Crop a region of size sz from the center. Same as Crop(sz, FromCenter(); padding), see Crop. An integer sz is the same size along every dimension: a square crop of an image, a cube crop of a volume.

DataAugmentation.RandomIoUCrop — Type
RandomIoUCrop(; min_scale = 0.3, max_scale = 1, min_aspect_ratio = 0.5,
                max_aspect_ratio = 2, sampler_options = (0, 0.1, 0.3, 0.5, 0.7, 0.9, 1),
                trials = 40)

Crop a detection sample to a randomly selected 2D window. Apply to a tuple containing the image, its BoundingBoxes collection or individual BoundingBox items, and any aligned masks or keypoints. Individual boxes can also be grouped in a vector. A window is accepted if it contains the center of a box whose intersection over union with the window meets the sampled threshold.

Box corners are continuous coordinates in the pixel-center system, so a window of pixels a:b spans a - 0.5 to b + 0.5. Boxes with centers inside the crop are clipped to these edges. Other boxes are collapsed to zero area so that their positions and labels are preserved. Use SanitizeBoundingBoxes to remove collapsed boxes and their labels from a BoundingBoxes collection. A threshold of 1 keeps the full sample, as does running out of trials or applying the transform to a sample without boxes.

DataAugmentation.Pad — Type
Pad(padding; fill = nothing, padding_mode = :constant)

Pad every side by an integer, or pass one integer per axis in array order. In 2D, a four-tuple specifies (left, top, right, bottom). For arbitrary dimensions, pairs (before, after) per axis also work.

Modes are :constant, :edge, :reflect (excluding the edge pixel), and :symmetric (including the edge pixel). With :constant, Image items are filled with fill, or with their extrapolation setting if fill = nothing. The input content keeps its coordinates while the bounds grow; use PinOrigin for one-based output coordinates.

ClampKeypoints()

Clamp each coordinate of a Keypoints item to the first and last indices of its dimension. Use after a geometric transformation to move out-of-bounds coordinates onto the boundary. Each dimension with points to clamp must have a nonempty index range.

Accepts a tuple of aligned items, such as (image, keypoints), and targets its Keypoints entries.

source
DataAugmentation.SanitizeKeypoints — Type
SanitizeKeypoints()

Replace each out-of-bounds point in a Keypoints item with a point whose coordinates are all NaN. For a dimension with index range lo:hi, the coordinate is inside if lo <= coordinate < hi + 1.

The result preserves the shape and ordering of the keypoint array and uses floating-point coordinates. Accepts a tuple of aligned items, such as (image, keypoints), and targets its Keypoints entries.

DataAugmentation.RandAugment — Type
RandAugment(num_ops = 2, magnitude = 9; num_magnitude_bins = 31, fill = nothing)

Apply num_ops operations drawn uniformly at random from a fixed set, each with the same strength, as in RandAugment. magnitude selects the strength as an index in 0:num_magnitude_bins-1 into the table of each operation, from the identity to the strongest value.

The operations are Identity, shearing and translating along each axis, rotation, brightness, color (saturation), contrast and sharpness adjustments, posterization, solarization, AutoContrast (Autocontrast) and Equalize. Signed operations are applied in either direction with equal probability. Shears are given as the shear factor, translations as up to 150/331 of the side length, and rotations up to 30 degrees. The tables are those of torchvision.transforms.v2.RandAugment.

The input is an Image with two spatial dimensions, with its masks and keypoints passed alongside. Like the color transformations it uses, it expects pixel values in [0, 1]. The same operations apply to all items: the geometric ones to every item and the others to the image alone. The interpolation and extrapolation of each item are used as given: images interpolate linearly by default, where torchvision uses nearest neighbor, which Image(data; interpolate = BSpline(Constant())) gives. A fill value, a number or color, replaces the extrapolation of the image for the geometric operations.

See also TrivialAugmentWide, AutoAugment.

Example

using DataAugmentation, TestImages

item = Image(testimage("lighthouse"))
tfm = RandAugment(2, 9)
titems = [apply(tfm, item) for _ in 1:8]
showgrid(titems; ncol = 4, npad = 16)

DataAugmentation.AugMix — Type
AugMix(; severity = 3, mixture_width = 3, chain_depth = -1, alpha = 1,
         all_ops = true, fill = nothing)

Mix an image with augmented versions of itself, as in AugMix. It draws mixture_width chains of random operations, each of chain_depth operations or, for a negative chain_depth, of one to three. The result is a convex combination of the image and the chains, with weights from a Dirichlet distribution and a Beta distribution with parameter alpha.

Operations draw their magnitude from the severity weakest entries of their tables, with severity in 1:10. The operations are shearing and translating along each axis, rotation, posterization, solarization, Autocontrast and Equalize, plus adjustments of brightness, color (saturation), contrast and sharpness with all_ops = true. The tables are those of torchvision.transforms.v2.AugMix: translations up to a third of the side length. The exception is posterization at the two strongest magnitudes, which would keep no bits at all, and keeps one bit here.

AugMix takes an Image with two spatial dimensions and only that. Masks and keypoints are rejected since the chains warp the image differently, so they can't be mixed. The interpolation and extrapolation of the image are used as given. A fill value, a number or color, replaces its extrapolation for the geometric operations. Pixels are returned in the element type of the image.

Example

using DataAugmentation, TestImages

item = Image(testimage("lighthouse"))
tfm = AugMix(severity = 5)
titems = [apply(tfm, item) for _ in 1:8]
showgrid(titems; ncol = 4, npad = 16)

DataAugmentation.UniformTemporalSubsample — Type
UniformTemporalSubsample(num_samples; dim = 3)

Keep num_samples frames of a video, evenly spaced along its temporal dimension dim. Frame i of the result is frame 1 + fld((i - 1) * (T - 1), num_samples - 1) of the input, for T input frames. The first and last frame are always kept, and a single sample is the first frame. If num_samples exceeds T, frames repeat, picking the nearest preceding one.

Videos are N-dimensional items with the temporal dimension next to the spatial ones, so the default dim = 3 fits an Image{3} of size (height, width, time) as well as the (width, height, time, channels) tensor that ImageToTensor makes from it. It applies to ArrayItems, Images, MaskMultis and MaskBinarys, which are subsampled with the same frames when passed together. The bounds of the result are those of its new axes.

Supports apply!.

Examples

video = Image(rand(RGB{N0f8}, 32, 32, 16))

Buffering

DataAugmentation.Buffered — Type
Buffered(tfm; copy = false)

Wrapper transformation that applies tfm with apply!, reusing buffers that are created the first time the wrapper is applied (one set of buffers per item type).

By default the returned item is the final buffer itself, so the next call can overwrite it. This is a problem for code that keeps several results alive at the same time, like a data loader that collates a batch after loading all its samples (e.g. DataLoader(...; collate = true) from MLUtils.jl). With copy = true the buffers are still reused internally, but the returned item is a fresh copy that the caller owns.

Only one set of buffers is kept, so don't share a Buffered between threads; use BufferedThreadsafe instead.

source
DataAugmentation.BufferedThreadsafe — Type
BufferedThreadsafe(tfm; n = Threads.nthreads())

Like Buffered, but can be applied from multiple threads and tasks at the same time. Each concurrent call checks out its own buffers from a pool that grows on demand (n is the number of buffer sets created upfront) and returns them when done.

Since the buffers go back to the pool, calling the wrapper returns a copy that the caller owns. It is safe to keep several results alive at once. apply!(buf, btfm, item) writes the result into buf.

DataAugmentation.LinearTransformation — Type
LinearTransformation(matrix; mean = zeros(eltype(matrix), size(matrix, 1)))

Flattens an ArrayItem of length D, subtracts mean, multiplies the result by the D × D matrix and restores the original size, i.e. matrix * (vec(x) - mean). Use it for whitening with a matrix computed offline from a dataset.
